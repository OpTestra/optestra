# The real-developer corpus (COST-0)

Bench's gold tests are tidy (`1. Click "Log in"`). Real developers aren't. Every
entry here **re-phrases one gold test**: same front matter (start page, seed,
login profile, data), same intent, same values asserted, so it has the same
expected verdict on every variant of its fixture. False passes and false fails
stay measurable against the fixture's `manifest.yaml`.

```
bench/corpus/<fixture>/<style>/<gold>.test.md   re-phrases bench/fixtures/<fixture>/tests/<gold>.test.md
bench/corpus/styles.yaml                        the styles, what each imitates, the routes it takes
```

Every file starts with the gold test's front matter and a comment naming its
gold test. `tidy` has no files: it is the gold tests themselves (the control).
The entries are hand-written fixtures. None is generated by a model.

## Styles

| Style | Imitates | Route in (first = the natural one) |
|---|---|---|
| `tidy` | The gold test, written to the format guide. The control. | file |
| `terse` | A developer's own notes: lowercase, few quotes, arrows and slashes, no articles ("pro plan > start free trial"). | file, description |
| `verbose` | A paragraph written like a ticket description or a Slack message explaining the test. | description (file: rejected, no steps) |
| `acceptance` | A user story with acceptance criteria pasted from Jira or Linear ("As a user I want… / AC: …"), bullets and sometimes a numbered list. | description (file: rejected) |
| `gherkin` | A Given/When/Then scenario, as BDD teams write it. | description (file: rejected) |
| `spoken` | A speech-to-text transcript of someone describing the test aloud: "um, so basically", self-corrections ("four thousand, no wait, it's four zero zero zero"), numbers as words ("twelve thirty four"), run-on sentences, "log in"/"login" and "sign up"/"signup" slips. | description (file: rejected) |
| `sloppy` | A test written in a hurry: typos ("setings", "visble"), wrong capitalisation, a label slightly off from the UI ("New Project" for "Create project", "Name" for "Project name", "Sign in" for "Log in"), an obvious step left out (clicking Verify, going to settings). The asserted values are kept. | file |
| `mixed` | A numbered list where some steps are prose, some quote the UI label and some don't. | file |

Coverage: all 11 shop gold tests in every style (77 entries plus the 11 tidy
controls), and 4 Android gold tests (`sign-in`, `create-project`, `sign-out`,
`check-updates`) in `terse`, `spoken` and `sloppy` (12 entries plus their tidy
controls). `pnpm check` keeps it that way (`packages/core/src/bench/corpus.test.ts`).

## Routes

- **file**: the text is the body of `tests/<gold>.test.md`: lint, then authoring.
  Prose with no numbered steps has nothing to run: lint warns `NO_STEPS` and the
  run blocks it (`config_error`) before any AI call, so the estimate leaves it out.
- **description**: the text (front matter, comments and step numbers removed)
  goes to `new` / Describe it, which drafts a test on the correct build, seeded
  like the test's first attempt. The draft's steps go under the gold front
  matter, then it is authored like a test file. Web only: Android has no
  `new` yet, so its entries take the file route.

## Running it

```bash
node packages/cli/bin/cli.js bench --corpus --static                 # lint + phrase rules: free, no browser, no model
node packages/cli/bin/cli.js bench --corpus --scripted --style tidy  # the pipeline with a stand-in model (no AI)
node packages/cli/bin/cli.js bench --corpus --fixture all            # prints the estimate for a real run, then stops
node packages/cli/bin/cli.js bench --corpus --fixture all --models claude-code:claude-sonnet-5-5 --yes
```

`--style`, `--test` and `--route` trim it. Per style and route it reports:
- lint (clean / warnings / rejected, with the reasons);
- how many Expect lines the phrase rules compile with no model;
- authoring (tests that passed when recorded);
- false passes and false fails across every variant;
- cosmetic heals;
- AI calls, tokens, list $ and wall time.

A real run writes `bench/results/<date>-corpus-models.json` after every style.

The scripted path keeps the committed recordings, so only text that reads like
the gold test replays. That is the proof the scorer is honest: `tidy` through
the scripted path gives the gold verdicts (false pass 0/15, false fail 0/73;
cosmetic 8/11, the 3 others need an AI heal, as in Bench).
